The automatic transform accepts exactly one verified Request/Http trigger with
an explicit string schema for internetMessageId, actualFrom and replyTo.
internetMessageId and actualFrom must be required. This is a synthetic normalized

Only top-level acyclic Compose and OpenApiConnection original actions with

The profile cannot inject arbitrary expressions, event fields or business edits.

Generic add-only fail-open design (the Help-specific gating differs as above):
- Intake telemetry is an independent root branch. Business never waits for it.
- Each completion telemetry scope waits only for original action success and
  intake scope settlement. Original successors never wait for telemetry.
- Identity, payload and connector live inside the telemetry scope. A final
  constant Compose handles Succeeded/Failed/Skipped/TimedOut of the write there.
  A failed identity/payload makes the write skipped; the final Compose still
  settles that telemetry branch. The terminal node has no fragile output read.
- Do NOT add an all-status catcher outside a scope that itself follows a
  business prerequisite. A Skipped scope caused by an original business failure
  must remain skipped; an external successful catcher could mask that failure.
- If intake failed or ResponseJson is unavailable/invalid, only later telemetry
  payloads fail. No fallback ProcessId is invented. Business still executes.
- Scope settlement means "telemetry attempt settled", NOT "event persisted".
  Native telemetry Write status/error monitoring and reconciliation are needed.
- No retry or resubmission of a business workflow repairs telemetry. Only the
  immutable telemetry request may be replayed in an authorized external worker.

The native workflow engine is not simulated completely by unit tests. The
success/skipped/failed terminal-branch aggregation, scope settlement, connector
configuration, cancellation behavior and timing require fault-injection pilot
verification before any release. Even a supported package is publishable=false.
Parallel telemetry may add duration and runs cannot promise lossless capture.
No financial servicing outcome is inferred merely from connector/agent success.
Definition completion authority must distinguish workflow invocation success
from independently proven tool/business success.
